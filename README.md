# 訪問看護　業務管理ステーション（日本訪問看護学会） - 引き継ぎメモ

## これは何か
日本訪問看護学会が所有する、訪問看護ステーションの「空き枠管理」「新規利用者の受け入れ提案」
「紹介元分析」を行う社内向けツール（アプリ名：訪問看護　業務管理ステーション）。管理者（スタッフ）
が共通のパスワードでログインし、全員で同じデータを見る・編集する形で使うことを想定している。
ログイン画面・ナビゲーション左上に学会ロゴと学会名を表示している（`index.php`の`.nav .brand`、
`login.php`の`.brand`。ロゴはPNGをBase64化して`<img src="data:image/png;base64,...">`として
直接埋め込んでいるため、追加のファイルアップロードは不要。ロゴを差し替える場合は新しい画像を
160×160px程度にリサイズしてBase64化し、両ファイルの該当箇所を置き換える）。

## 技術構成
- フロントエンド：Vanilla JS + HTML + CSS（`index.php`）。フレームワーク・ビルド工程なし。
- バックエンド：PHP + MySQL（CoreServerなどの一般的な共有レンタルサーバーで動く構成）。
- データはMySQLの `app_state` テーブルに1行（JSON文字列）として保存し、
  `api/state.php` 経由でフロントエンドと共有する（全管理者が同じデータを見る）。
- 認証は管理者共通の1つのパスワード（`config.php` にハッシュを保存、PHPセッションでログイン状態を管理）。
- デプロイ手順は `DEPLOY.md` を参照。

## 画面構成
① 空き状況〈看護師〉／② 空き状況〈セラピスト〉／③ 新規登録・提案／④ 利用者検索（旧・終了処理）／
⑤ 入院管理表／⑥ リスト分析（旧・紹介元分析）／⑦ 月次レポート／⑧ スタッフ管理／⑨ 設定

## データモデル（index.php内のJS、MySQLの app_state.data カラムにJSON文字列として保存）
```
state = {
  staff: [{name, role: '看護師'|'セラピスト'|'事務員', qualifications: string[]}, ...],
  // qualifications の例: ['理学療法士'], ['特定行為看護師','皮膚・排泄ケア認定看護師'] など。複数可・自由記述の資格も可
  slotLabels: { '看護師': string[], 'セラピスト': string[] }, // 時間帯の名称。職種ごとに独立（並び替え可能）
  staffWorkSlots: { [staffName]: { [day]: number[] } }, // 曜日ごとに「その日のうち実際に勤務する時間帯（枠index）」の配列
  // 例：{ "山田花子": { "月": [0,1,2,3,4,5], "土": [0] } } → 月曜は全枠勤務、土曜は最初の枠だけ勤務
  staffBuffer: { '看護師': number, 'セラピスト': number }, // ①②の空き枠数計算・③の新規提案の候補選定の両方で差し引くスタッフ人数
  bookings: {
    [bookingId]: {
      staff, day, slotIdx,
      weeks: number[],                  // 1-5。[1,2,3,4,5]なら毎週、[1,3]なら隔週、[1,3,5]なら隔週(第1・3・5週)など
      patternValue,                     // 'weekly'|'daily'|'daily7'|'biweekly_13'|... （登録時の頻度パターン）
      name, disease, insuranceType, serviceDuration, alone, careManager, hospital, district, timeNote, note, startDate,
      pairId: string | null,
      hospitalized: boolean               // 入院中フラグ（デフォルトfalse相当。省略時はfalse扱い）
      // insuranceType: '医療保険'|'介護保険'|'精神'|'小児'（任意）。serviceDuration: '30'|'60'|'90'（分）
      // district: ⑨設定「地区マスタ」に登録した地区名（任意、例：さいたま市緑区）
      // pairId はご夫婦など同じ枠に2名を登録した場合、両者に同じ値を持たせて紐付けるためのID。
      // 実体としては2件の独立したbooking（別々のid）なので、編集・終了はそれぞれ個別に行える。
      // 対になっている予約は pairedBookingAt(booking) で取得できる。
      // hospitalized は④利用者検索・⑤入院管理表・①②のモーダル内チェックボックスのいずれからでも
      // ON/OFFできる（toggleHospitalized()）。booking自体は削除・移動せず、フラグを立てるだけ。
      // ON にすると①②の該当マスが黒色（.blk.hospitalized）になり、⑤入院管理表に一覧表示される。
      // 空き枠の集計・自動提案上は引き続き「使用中」の枠として扱われる（他の利用者には提案されない）。
    }
  },
  eventLog: [{type:'新規'|'終了', date, name, staff, day, slot, careManager, hospital, reason?}, ...],
  // reason（終了理由）は type:'終了' のときのみ。'入所'|'看取り'|'卒業' のいずれか
  referralSources: { careManagers: string[], hospitals: string[] },
  districts: string[] // 地区マスタ（⑨設定で追加・削除。③新規登録・提案の「地区」選択肢になる）
}
```
- 1つの(staff, day, slotIdx)に対して複数の`booking`が共存できる（隔週・月次ローテーション対応、
  および同じ枠に2名を登録するご夫婦・ペア登録も同様の仕組みで実現している）。
  週の重複チェックは`isRotationFree()` / `isFullyFree()`を参照。
- `staff`配列の並び順がそのまま①②の表示順になる（⑧スタッフ管理の↑↓で自由に並べ替え可能）。名前も直接書き換え可能
  （`renameStaffMember()`が`staffWorkSlots`・`bookings`・`eventLog`内の旧名称もまとめて置き換える）。
- スタッフの資格・専門性（`qualifications`）は複数登録可能。理学療法士等のプリセットに加え、
  「○○認定看護師」「○○専門看護師」「他ライセンス」は自由記述の接頭辞を付けて登録できる。
  画面表示（`roleLabel()`）は資格があればそちらを優先し、なければ`role`を表示する。
  `事務員`は①②の対象外（⑧の職員名簿にのみ表示）。
- 時間帯（`slotLabels`）は看護師・セラピストで完全に別の配列。⑨設定でそれぞれ独立して追加・削除・
  並べ替え・名前変更ができる（`slotLabelsFor(role)` / `slotCount(role)`を参照）。
- スタッフの勤務体系（`staffWorkSlots`）は曜日単位ではなく「曜日×時間帯（枠）」単位で管理する。
  ⑨設定の勤務体系表は①の空き状況と同じ見た目のマス目（`.blk`ボタン）で、タップするとその
  スタッフ・その曜日・その枠だけをON/OFFできる（`worksOnSlot(staff,day,slotIdx)`で判定）。
  お昼で退勤する日、特定の枠だけ土日出勤するスタッフなど、曜日によって勤務する枠が異なる
  ケースに対応している。`worksOn(staff,day)`はその曜日にひとつでも勤務枠があるかの判定に使う
  （空き状況の土日欄を出すかどうかなどに利用）。
- ①②の「空き余地」の集計と自動提案の曜日探索は、土曜・日曜を定休日として自動的には対象にしない
  （`orderedDays()`参照）。土日欄はマス目ではなく、その日にその枠のどこかで実際に予約がある
  利用者名だけを箇条書きで表示する（クリックで通常どおり編集・終了操作が可能）。特定の利用者が
  土日を希望する場合は、⑨でそのスタッフの該当曜日・該当枠を個別にONにしたうえで通常どおり登録
  すればよい。訪問頻度パターンに「毎日（月〜日・週7回、土日訪問あり）」（`daily7`）を用意しており、
  これを選ぶと自動提案・自動登録も土日を含めて探索する（`includeWeekend`フラグで制御）。
  また③新規登録・提案には「特例」チェックボックス（`#f-weekend-exception`）があり、これをONにすると
  ⑨設定の勤務体系（ON/OFF）に関わらず土日を候補に含めて提案する（`weekendException`パラメータで
  `findWeeklySuggestions()` / `findRotationSuggestions()`に伝搬）。⑨設定自体は書き換えないその場限りの
  例外登録で、登録後は①②の該当曜日欄に通常どおり利用者名が箇条書きで表示される。土日に希望日を
  指定したい場合は希望曜日チップで「土」「日」を選択できる。
- ①②の「週2（2枠）／人」「週1（1枠）／人」は、曜日ごとの空き余地の合計（月〜金）から算出する
  独立した数字（曜日別カードとは別枠で表示）。
- 「空き枠数の計算調整」（⑨設定の看護師・セラピストごとの差引人数）は、①②の表示だけでなく
  ③新規登録・提案の候補選定にも反映される。実装は`suggestionPool(role)`で、勤務予定人数が
  最も少ない（＝一番余裕があるように見える）スタッフから順に差引人数分を候補から除外する方式。
- 登録済みの利用者様のサービス内容を増やしたい場合は、③新規登録・提案で同じ氏名を入力すると
  「既に◯件ご利用中です」という案内が表示され、登録済みの内容（疾患名・主保険・サービス時間・
  居宅介護支援事業所・医療機関）をそのまま引き継いで新しい枠を追加登録できる
  （`findExistingBookingsByName()` / `updateExistingPatientNotice()`）。逆に減らしたい場合は
  ④利用者検索から該当の枠だけを個別に終了すればよい。
- 初期データ（新規登録時・「共有データを初期状態に戻す」実行時）は`staff`・`slotLabels`・`staffWorkSlots`
  のみ`SEED`定数から復元する。`bookings`（利用者情報）は常に空の状態から始まる。
  設定はそのままに利用者情報だけを消したい場合は、⑨設定の「利用者情報を初期化」を使う（2段階確認あり）。
- 利用者情報（氏名・疾患名・主保険・居宅介護支援事業所・曜日・時間帯など）は、
  ①②のマスに表示されるモーダル内の「編集する」から後で修正できる（`openSlotModal()`の
  インライン編集フォーム）。曜日・時間帯を変更すると、変更先が空いているかチェックしたうえで
  予約そのものを移動する。ご夫婦・ペア登録の場合も、同じ枠に表示される2枚のカードをそれぞれ
  個別に編集・終了できる。
- 各画面の「🖨 PDF出力」ボタンはブラウザの印刷機能（`window.print()`）を呼び出す実装。専用ライブラリは
  使わず、印刷時は`@media print`でナビや操作ボタンを非表示にして該当パネルのみを出力する。
- ⑥リスト分析・⑦月次レポートには「📥 CSV出力」ボタンもあり、そのパネル内に表示されているすべての
  表（`table.grid`）を、見出し（h3）ごとにまとめて1つのCSVファイルとしてダウンロードできる
  （`exportPanelCsv(panelId, filename)`。Excelで文字化けしないようUTF-8 BOM付きで出力）。
- ⑦月次レポートには、登録・終了の月別集計や終了理由の内訳に加えて、現在の利用者を対象にした
  疾患名・主保険・独居・地区の内訳表も表示する（⑥リスト分析の紹介元分析と同じ集計ロジックを再利用）。
  地区は⑨設定の「地区マスタ」で事業所ごとに自由に登録する（例：さいたま市緑区、川口市）。
- ①②の空き状況ヘッダー右側には「🔔 受け入れ枠アラート」を表示する。月〜金・曜日×時間帯（枠）ごとに、
  空き枠数の調整（バッファ）を差し引いたうえで空いているスタッフ数を数え、2件以上空いている
  枠を一覧表示する（`computeSlotAlerts(role, threshold)`）。しきい値は関数の引数で変更できる。
  表示位置は週間サマリーカードの右側（`.ov-body`）に限定しており、下の勤務表（土日を含む）は
  従来どおり全幅で表示される（勤務表と横並びにすると土日欄が圧迫されるため分離している）。
  左側のサマリーカード列とアラート枠の高さは、件数によって左右の高さが揃わず下に余白が
  できてしまわないよう、`renderOverview()`の末尾で`syncOverviewAlertHeight(role)`を呼び、
  サマリーカード列の実測高さ（`#ovMain-<role>`）をアラート枠（`#ovAlert-<role>`）にJSで
  反映して揃えている（アラート内の一覧はその高さの中で内部スクロールする）。スタッフ0名時の
  早期returnでも揃えるようにしているほか、`ResizeObserver`で`#ovMain-<role>`を監視し続け、
  表示後にサマリーカード列の高さが変わった場合でも自動的に揃え直す。
  なお空き状況の「土曜・日曜は定休日のため…」という注記文は、ユーザー要望により削除済み。
  サマリーカード列（`.ov-main`）には`max-width:620px`を指定している。これが無いと、
  「空き枠数の計算調整」の注記文（バッファが0より大きいスタッフ職種でのみ表示される長い1文）
  がラップされずに`flex:0 0 auto`のshrink-to-fit幅を押し広げてしまい、看護師側だけアラート枠
  （`flex:1`で残り幅を埋める）が極端に狭くなって1列表示になる、という左右非対称な不具合が
  起きていた。max-widthで固定してテキストを折り返させることで、注記文の有無に関わらず
  アラート枠の横幅が常に揃うようにしている。あわせて注記文自体も「※〈職種〉 N名分を
  勤務予定人数から差し引いて計算しています」まで短縮し（補足の「⑨設定で変更できます…」
  部分は削除）、視認性を上げている。
- ④利用者検索（旧・終了処理）は、単に予約を終了するだけの画面ではなく、氏名検索でヒットした
  利用中の予約1件ずつに対して「編集する」（①②のスロットモーダルを`openSlotModal(staff,day,slotIdx)`
  で直接開き、曜日・時間帯や各種情報を変更できる）・「入院中」チェックボックス・「終了する」の
  3つの操作をその場で行えるようにしたもの（`buildBookingRow()`が共通の行テンプレート）。
- 「入院中」チェックは`toggleHospitalized(id, checked)`で`booking.hospitalized`を切り替えるだけで、
  予約自体は削除・移動しない（一時的に入院しても、退院後は同じ枠がそのまま復帰する）。
  ON にすると①②の該当マスが黒色（`.blk.hospitalized`、凡例に追加済み）で表示され、土日欄（一覧
  表示）でも氏名の後ろに「（入院中）」と表示される。空き枠の集計・自動提案では引き続き
  「使用中」の枠として扱われる（入院中でも他の利用者には提案されない）。
  トグル自体は④利用者検索の一覧・⑤入院管理表の一覧・①②のスロットモーダル内チェックボックスの
  どこからでも操作でき、どこで変更しても他の画面に即座に反映される。
- ⑤入院管理表（`renderInpatientList()`）は、`booking.hospitalized===true`の予約だけを
  ④利用者検索と同じ行テンプレートで一覧表示する専用画面。入院中の利用者をまとめて把握し、
  退院時にチェックを外す・そのまま終了する、といった運用を想定している。

## 既知の制約・今後の検討事項
1. **同時編集は後勝ち（last-write-wins）**：複数管理者がほぼ同時に保存すると、後から保存した方の
   内容で上書きされる（競合検知や警告表示はまだ実装していない）。編集がぶつかることが実際に
   問題になるようなら、楽観ロック（保存時のタイムスタンプ比較）の追加を検討。
2. **入力値のエスケープ**：利用者名・疾患名などは画面表示時にHTMLエスケープしていない
   （信頼できる内部スタッフのみが入力する想定のため、現状は許容している）。外部にも公開する場合は要対応。
3. **Excelとの連携なし**：元のExcel（訪問予定表_最新版.xlsx）とこのアプリは同期していない。
   どちらかをメインの記録にするか、連携の仕組みを作るか要検討。
4. **紹介元分析の「割合」の定義**：現状は「自社の現在の利用者全体に占める、その紹介元のシェア」
   として計算している（各事業所側の全利用者数に対する割合ではない）。要件次第で変更が必要。
5. **利用者の同一性判定が名前ベース**：同姓同名がいると紹介元分析などで名寄せが誤る可能性がある。
   本格運用する場合はID採番を検討。
6. **管理者ログインは共通パスワード1つ**：誰がいつ編集したかは記録されない。個人ごとの操作履歴が
   必要になった場合は、アカウントを分ける仕組みへの変更を検討。
